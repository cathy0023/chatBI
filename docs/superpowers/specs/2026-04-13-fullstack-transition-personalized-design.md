# 全栈转型个人化路径设计文档

> 创建日期: 2026-04-13
> 状态: Finalized

> 适用对象: 前端开发者 → Python 后端，碎片化时间，每日 < 1 小时

---

## 一、用户画像

| 维度 | 现状 |
|------|------|
| 每日投入 | < 1 小时（碎片化） |
| 团队规模 | 2-3 人小团队 |
| 目标层级 | A（接手现有）+ B（评审API）+ C（独立交付） |
| 后端起点 | 零基础，完全没接触过 |
| AI 工具 | Claude Code（主力） |
| 优先语言 | Python（急迫） |

---

## 二、核心挑战

**时间极度碎片化 + 目标极度 ambition = 必须极度聚焦**

每日 < 1 小时，按传统"学语法→学框架→学架构"的线性路径，大概需要一年才能到 C。还不如不学。

**突破口**：Claude Code 是最强加速器。但它加速的是"写"，不是"想"。要用 AI 替代查文档、解释概念、演示模式，而不是替代判断。

**核心转变**：
- 不是"学会写代码"，而是"学会判断代码对不对"
- 不是"学完再做事"，而是"做事中学习"
- 碎片化时间用来：提问、review、思考；整块时间用来：做项目

---

## 三、学习路径：三阶段 × 12 周

```
阶段一（Week 1-3）：后端代码长什么样
阶段二（Week 4-8）：能看懂 Python 项目
阶段三（Week 9-12）：能独立交付一个后端功能
```

---

### 阶段一：后端代码长什么样（Week 1-3）

**目标**：理解，不是写。能用自己的话解释后端代码在做什么。

**每日投入策略**：
- 碎片时间（20分钟）：Claude Code Ask 模式，问概念
- 整块时间（40分钟）：Claude Code Act 模式，生成代码 + 审查

**每周任务**：

| 周次 | 任务 | AI 使用方式 | 验收标准 |
|------|------|------------|---------|
| Week 1 | 用 Claude Code 生成一个 FastAPI CRUD API | 生成 + 解释每个文件 | 能向非技术人员解释这个 API 是怎么跑起来的 |
| Week 2 | 用 Claude Code 生成数据库操作代码 | 生成 + 解释 ORM vs SQL | 能说出"ORM 背后还是在写 SQL" |
| Week 3 | 把代码跑起来，用 Claude Code Debug | 故意制造 bug，让 AI 找 | 能说清楚报错信息是什么意思 |

**阶段交付物**：
- 一个跑起来的 FastAPI 服务（本地）
- 一份用自己的话写的"后端代码理解笔记"（300字）

---

### 阶段二：能看懂 Python 项目（Week 4-8）

**目标**：读懂，不是开发。直接切入团队 Python 项目。

**前提**：即将接手 Python 项目，不能再纸上谈兵。

**每日投入策略**：
- 碎片时间：Claude Code 阅读模式，读团队项目代码
- 整块时间：Claude Code Ask 模式，理解架构设计

**每周任务**：

| 周次 | 任务 | AI 使用方式 | 验收标准 |
|------|------|------------|---------|
| Week 4 | 找团队项目中最小的模块（< 200行） | 画流程图 + 解释代码 | 不看 AI，能画出这个模块的流程图 |
| Week 5 | 读懂数据库相关代码 | 解释 SQLAlchemy 用法 | 能说出"这个查询是在查什么" |
| Week 6 | 读懂 API 路由和业务逻辑 | 理解参数校验 + 错误处理 | 能向队友解释某个 API 的输入输出 |
| Week 7 | 读懂测试和 CI 配置 | 运行测试 + 看 GitHub Actions | 能独立运行项目测试 |
| Week 8 | 用 Claude Code 做一次 Code Review | AI 提问题 + 评审问题质量 | 能提出 3 个有意义的代码问题 |

**阶段交付物**：
- 一份"团队项目理解文档"（每个模块 50 字说明）
- 一次 Code Review 的记录（至少 3 个有意义的评论）

---

### 阶段三：能独立交付一个后端功能（Week 9-12）

**目标**：交付，不是学习。从"能看懂"升级到"能做事"。

**前提**：阶段二完成后，应该能看懂 Python 项目了。

**每日投入策略**：
- 碎片时间：想清楚要做什么、问 Claude Code 方案
- 整块时间：Claude Code 生成代码 → review → 修改 → 提交

**每周任务**：

| 周次 | 任务 | AI 使用方式 | 验收标准 |
|------|------|------------|---------|
| Week 9 | 接一个小任务（bug 或小功能） | AI 生成方案 → 评审方案 → 再生成代码 | 方案通过后，才让 AI 生成代码 |
| Week 10 | 完成第一次独立 PR | 自己 review 自己的代码 | PR 被合并 |
| Week 11 | 理解部署和上线 | 看 Docker 配置 + CI/CD 流水线 | 能说出代码是怎么从 PR 到生产的 |
| Week 12 | 独立做一次故障排查 | 分析历史故障 + 5Why 分析 | 能写出故障分析的 5Why |

**阶段交付物**：
- 一个被合并的 PR
- 一份故障分析文档

## 四、AI 使用规范（贯穿全程）

### Claude Code 使用三问

每次使用 Claude Code 时，问自己三个问题：

1. **这代码我能用手写出来吗？**
   - 能 → 继续
   - 不能 → 抄一遍，理解原理，再继续

2. **这段代码的边界 case 是什么？**
   - 空输入？并发？超时？
   - 这些必须自己补，AI 只生成 happy path

3. **这段代码会不会埋雷？**
   - N+1 查询、连接泄漏、事务边界不清
   - 能识别雷，比写出代码更重要

### 模式选择

| 场景 | 推荐模式 | 说明 |
|------|---------|------|
| 理解概念 | Ask 模式 | 直接问它解释，不生成代码 |
| 生成代码 | Act 模式 | 让它生成，然后审查 |
| 读懂代码 | Read + Ask | 先读，再用 Ask 追问 |
| Code Review | Review 模式 | 让它提问题，你来评审 |

## 五、与通用方案的差异

| 维度 | 通用方案（16周） | 本方案（12周） |
|------|---------------|--------------|
| 入口 | Node.js/TS 语法 | 直接切入 FastAPI + Python |
| 学习方式 | 先学后做 | 做中学 |
| 时间适配 | 2-4 小时/天 | < 1 小时/天 |
| 项目切入 | 无 | Week 4 直接读团队代码 |
| AI 角色 | 不涉及 | 主力工具 |
| 阶段一目标 | 语法 | 理解 |
| 阶段二目标 | 框架 | 读懂项目 |
| 交付训练 | Week 13-16 | Week 9-12 |

## 六、风险与应对

| 风险 | 应对 |
|------|------|
| 碎片时间无法形成连续思考 | 每天至少问 AI 一个问题，保持上下文连续 |
| AI 生成代码理解了但写不出来 | 强制手抄关键代码片段，不跳过 |
| 阶段二读团队代码卡住 | 用 Claude Code 的 Ask 模式逐段理解 |
| 阶段三找不到合适的任务练手 | 主动向团队申请一个小任务 |

|------|---------|
| 阶段一 | 能用自己的话向非技术人员解释 FastAPI 是怎么处理一个请求的 |
| 阶段二 | 能独立回答队友关于某个 API 的问题 |

## 八、后续拓展（阶段三之后）

完成阶段三后，可选方向：
- **Go 切入**：用同样的方法（Ask + Act + Review）切入 Go 项目
- **架构能力**：开始关注 API 设计评审、微服务拆分
- **DevOps**：深入 CI/CD 流水线、监控告警
- **团队管理**：从自己交付 → 带别人交付
